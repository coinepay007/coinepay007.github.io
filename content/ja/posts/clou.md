# **Cloudflare CDNの設定方法：2027年版・完全ガイド**

## **はじめに**

Cloudflare CDNは、Webサイトの表示速度を向上させ、セキュリティを強化し、オリジンサーバーの負荷を軽減するためのサービスです。世界各地に設置されたサーバーを通じてコンテンツを配信することで、訪問者がWebサイトにより速くアクセスできるようにします。

個人ブログ、企業サイト、オンラインショップなど、どのようなWebサイトを運営している場合でも、Cloudflare CDNを導入することで、サイトのパフォーマンスと安定性の向上が期待できます。

## **1. Cloudflare CDNとは？**

Cloudflareは、CDN、DNS、セキュリティ、Webサイトのパフォーマンス最適化などのサービスを提供するプラットフォームです。

CDNとは「Content Delivery Network（コンテンツ配信ネットワーク）」の略称です。Webサイトのコンテンツを世界各地のサーバーに分散して保存し、訪問者に近いサーバーからコンテンツを配信します。

Cloudflareを利用する主なメリットは次のとおりです。

- Webページの読み込み速度を改善できる
- オリジンサーバーへのアクセス負荷を軽減できる
- DDoS攻撃に対する保護を利用できる
- DNSを一元管理できる
- SSL証明書とHTTPS接続を利用できる
- キャッシュルールによってコンテンツ配信を最適化できる

## **2. 設定前に準備するもの**

WebサイトをCloudflareに接続する前に、次のものを準備してください。

1. 独自ドメイン
2. ドメイン管理画面へのログイン権限
3. 現在設定されているDNSレコードの情報
4. ホスティングサービスまたはサーバー管理画面へのアクセス権限

メールサービスやドメインに関連付けられた他のサービスが停止しないように、現在のDNSレコードを事前に保存しておくことをおすすめします。

## **3. Cloudflareアカウントを作成する**

Cloudflareの公式サイトにアクセスし、アカウントを作成します。

登録が完了したら、次の手順で進めます。

1. Cloudflareのダッシュボードを開く
2. サイトを追加するオプションを選択する
3. 自分のドメイン名を入力する
4. 設定を続行する

Cloudflareは既存のDNSレコードを自動的にスキャンし、インポートを試みます。

## **4. ドメインをCloudflareに追加する**

ドメイン名を入力すると、Cloudflareからプランの選択を求められます。

個人サイトや小規模なプロジェクトであれば、最初は無料のFreeプランで十分な場合が多いです。

プランを選択したら、インポートされたDNSレコードを確認してください。

## **5. DNSレコードを確認する**

DNSレコードの確認は、Cloudflareの設定で特に重要な作業です。

Cloudflareは既存のDNSレコードを自動的にインポートできますが、すべての情報が正しく登録されているか確認する必要があります。

主なDNSレコードの種類は次のとおりです。

**A Record**

ドメイン名をIPv4アドレスに紐付けます。

**AAAA Record**

ドメイン名をIPv6アドレスに紐付けます。

**CNAME Record**

サブドメインを別のドメイン名に転送します。

**MX Record**

ドメイン宛てのメールを受信するメールサーバーを指定します。

**TXT Record**

ドメイン認証、SPF、DKIMなどの設定に使用されます。

独自ドメインのメールサービスを利用している場合は、特にMXレコードとTXTレコードを慎重に確認してください。

## **6. Cloudflare Proxyを有効にする**

DNSレコードの一覧には、一部のレコードの横に雲のアイコンが表示されます。

主に次の2つのモードがあります。

**Proxied（オレンジ色の雲）**

HTTPおよびHTTPSの通信がCloudflareのネットワークを経由します。CDN機能やCloudflareのセキュリティ機能を利用できます。

**DNS Only（灰色の雲）**

CloudflareはDNSの名前解決のみを行い、通信はオリジンサーバーに直接接続されます。

WebサイトのAレコードやCNAMEレコードでは、CDNやセキュリティ機能を利用したい場合にProxiedを有効にできます。

MXレコードなど、プロキシに対応していないレコードはDNS Onlyのままにしてください。

## **7. ドメインのネームサーバーを変更する**

DNSレコードの確認が終わると、Cloudflareから2つのネームサーバーが提供されます。

例えば、次のような形式です。

- [alice.ns.cloudflare.com](http://alice.ns.cloudflare.com)
- [bob.ns.cloudflare.com](http://bob.ns.cloudflare.com)

実際のネームサーバー名はドメインごとに異なります。

ドメインを購入したサービスの管理画面にログインし、既存のネームサーバーをCloudflareが指定したものに変更してください。

変更を保存したら、DNSの反映を待ちます。

反映には数分から24時間程度、場合によってはそれ以上かかることがあります。

## **8. SSL/TLSを設定する**

ドメインが有効になったら、CloudflareのダッシュボードからSSL/TLSの設定画面を開きます。

ここでは、いくつかの暗号化モードを選択できます。

**Flexible**

訪問者とCloudflare間の通信は暗号化されますが、Cloudflareとオリジンサーバー間の通信は暗号化されません。

**Full**

Cloudflareとオリジンサーバー間でもHTTPSを使用しますが、オリジンサーバーの証明書の有効性を厳密には検証しません。

**Full (Strict)**

通信を暗号化し、オリジンサーバーのSSL証明書が有効であることも検証します。

サーバーに有効なSSL証明書が設定されている場合は、Full (Strict)の利用をおすすめします。

WebサイトがHTTPSに正しく対応している場合、Flexibleを使用するとリダイレクトの問題が発生する可能性があるため、避けることをおすすめします。

## **9. キャッシュを設定する**

キャッシュとは、Cloudflareが画像、CSSファイル、JavaScriptファイルなどのリソースを一時的に保存する仕組みです。

これにより、訪問者はCloudflareのサーバーからリソースを取得できるため、すべてのリクエストがオリジンサーバーに届く必要がなくなります。

キャッシュを設定する手順は次のとおりです。

1. Cachingセクションを開く
2. 利用可能なキャッシュ設定を確認する
3. 適切なキャッシュレベルを選択する
4. リソースをキャッシュに保存する期間を設定する

すべてのページを確認せずにキャッシュすることはおすすめしません。ログインページ、ショッピングカート、ユーザーごとに内容が異なるページなどには、個別のルールが必要になる場合があります。

## **10. Cache Rulesを設定する**

Cloudflareでは、キャッシュの動作を細かく制御するためのルールを作成できます。

例えば、次のような設定が可能です。

- 画像や静的ファイルをキャッシュする
- 管理画面のページをキャッシュ対象から除外する
- ログインページをキャッシュ対象から除外する
- 特定のサブドメインに異なるルールを適用する
- コンテンツの種類に応じてキャッシュ期間を変更する

WordPressサイトでは、管理画面や頻繁に更新されるコンテンツが誤ってキャッシュされないように注意してください。

## **11. Cloudflareのキャッシュを削除する**

Webサイトを更新したにもかかわらず、訪問者に古いバージョンが表示される場合、Cloudflareに古いコンテンツがキャッシュされている可能性があります。

この問題を解決するには、次の手順で操作します。

1. Cachingセクションを開く
2. Purge Cacheを選択する
3. 希望する削除方法を選択する
4. 操作を確定する

キャッシュ全体を削除することも、特定のURLだけを指定して削除することもできます。

頻繁にサイトを更新する場合は、関連するURLだけを削除する方法が効率的です。

## **12. Cloudflare CDNが正常に動作しているか確認する**

設定が完了したら、Webサイトの通信が実際にCloudflareを経由しているか確認しましょう。

ブラウザの開発者ツールを開き、読み込まれたリソースのHTTPレスポンスヘッダーを確認します。

特に確認したいヘッダーの一つが次のものです。

`cf-cache-status`

このヘッダーには、次のような値が表示されます。

- HIT：リソースがキャッシュから配信された
- MISS：キャッシュに存在せず、オリジンサーバーから取得された
- BYPASS：キャッシュが回避された
- DYNAMIC：キャッシュ対象として扱われていない
- EXPIRED：キャッシュされたデータの有効期限が切れている

すべてのリクエストがHITになる必要はありません。動的なページはオリジンサーバーから直接配信される場合があります。

## **13. Cloudflareの設定でよくある問題**

**521エラー**

オリジンサーバーがCloudflareからの接続を拒否している可能性があります。

サーバーが正常に動作しているか、ファイアウォールがCloudflareのIPアドレスからの接続を許可しているか確認してください。

**522エラー**

Cloudflareがオリジンサーバーから時間内に応答を受け取れない場合に発生します。

サーバーのパフォーマンス、ファイアウォールのルール、ネットワーク接続を確認してください。

**SSLエラー**

CloudflareのSSL/TLSモードと、オリジンサーバーの証明書設定が一致していない場合に発生することがあります。

SSL証明書と選択した暗号化モードを確認してください。

**Webサイトに古いコンテンツが表示される**

古いバージョンがキャッシュに残っている可能性があります。

キャッシュを削除し、ドメインに適用されているキャッシュルールを確認してください。

## **14. Cloudflare Freeと有料プランの違い**

CloudflareにはFreeプランのほか、複数の有料プランが用意されています。

**Freeプラン**

ブログ、個人サイト、小規模なプロジェクトに適しています。基本的なDNS、CDN、セキュリティ機能を利用できます。

**有料プラン**

追加機能、高度なルール設定、より充実したセキュリティ機能、異なるサポート体制などを必要とするWebサイトに適しています。

有料プランにアップグレードする前に、追加機能が本当に必要かどうかを確認しましょう。

## **15. 設定完了後のチェックリスト**

設定が正しく完了したか、次の項目を確認してください。

- ドメインがCloudflareに追加されている
- ネームサーバーが正しく変更されている
- DNSレコードが正しく設定されている
- MXレコードとTXTレコードが保持されている
- 必要なWebレコードでProxyが有効になっている
- SSL/TLSモードが正しく設定されている
- WebサイトがHTTPSで表示される
- キャッシュルールが動的な機能に悪影響を与えていない
- Cloudflareの有効化後もWebサイトが正常に動作している

## **まとめ**

Cloudflare CDNの導入は、Webサイトのパフォーマンス、セキュリティ、安定性を向上させる効果的な方法です。

ドメインの追加、DNSレコードの確認、ネームサーバーの変更、SSL/TLSの設定、キャッシュの最適化を行うことで、専門的な技術知識がなくてもCloudflareの基本機能を活用できます。

多くのWebサイトでは、最初は無料プランで十分です。プロジェクトが成長した段階で、追加機能が必要かどうかを検討するとよいでしょう。

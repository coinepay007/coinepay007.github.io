# คู่มือ Cloudflare: 10 ฟีเจอร์สำคัญที่มือใหม่ควรรู้

หากคุณต้องการเพิ่มความเร็วในการโหลดเว็บไซต์ เสริมความปลอดภัย และทำให้เว็บไซต์มีความเสถียรมากขึ้น Cloudflare ถือเป็นบริการที่มีประโยชน์อย่างมาก

Cloudflare มีเครื่องมือหลากหลาย เช่น การจัดการ DNS, CDN, SSL/TLS, การป้องกัน DDoS และ Web Application Firewall แม้จะเป็นมือใหม่ก็สามารถปรับปรุงประสิทธิภาพและความปลอดภัยของเว็บไซต์ได้ด้วยการตั้งค่าพื้นฐานเพียงไม่กี่ขั้นตอน

บทความนี้จะแนะนำ Cloudflare ตั้งแต่พื้นฐานไปจนถึง 10 ฟีเจอร์สำคัญที่มือใหม่ควรรู้ พร้อมวิธีตั้งค่าและแนวทางแก้ไขปัญหาที่พบบ่อย

## 1. Cloudflare คืออะไร?

Cloudflare เป็นบริการที่ช่วยเพิ่มความเร็วเว็บไซต์ เสริมความปลอดภัย และจัดการเครือข่ายสำหรับเว็บไซต์

เมื่อคุณเชื่อมต่อเว็บไซต์เข้ากับ Cloudflare เครือข่ายของ Cloudflare จะทำหน้าที่เป็นตัวกลางระหว่างผู้เข้าชมเว็บไซต์กับเซิร์ฟเวอร์ต้นทาง (Origin Server)

ประโยชน์หลักของ Cloudflare ได้แก่:

- เพิ่มความเร็วในการโหลดเว็บไซต์ผ่าน CDN
- ป้องกันการโจมตีแบบ DDoS
- เข้ารหัสการรับส่งข้อมูลด้วย SSL/TLS
- ช่วยให้การจัดการ DNS ง่ายขึ้น
- กรองทราฟฟิกที่น่าสงสัยและการเข้าถึงที่ไม่ได้รับอนุญาต
- ลดภาระของเซิร์ฟเวอร์ต้นทางด้วยระบบแคช (Caching)

Cloudflare มีแพ็กเกจฟรีให้ใช้งาน จึงเหมาะสำหรับบล็อกส่วนตัวและเว็บไซต์ขนาดเล็กที่ต้องการเริ่มต้นใช้งานโดยไม่ต้องเสียค่าใช้จ่าย

## 2. การสมัครบัญชี Cloudflare และเพิ่มเว็บไซต์

ก่อนใช้งาน Cloudflare คุณต้องสร้างบัญชีและเพิ่มโดเมนที่ต้องการจัดการก่อน

### 2.1 สมัครบัญชี

เข้าไปที่เว็บไซต์อย่างเป็นทางการของ Cloudflare:

[https://www.cloudflare.com/](https://www.cloudflare.com/)

กรอกอีเมลและรหัสผ่านเพื่อสร้างบัญชี จากนั้นยืนยันอีเมลหากระบบร้องขอ

### 2.2 เพิ่มเว็บไซต์

หลังจากเข้าสู่ระบบแล้ว ให้ไปที่แดชบอร์ดและเลือก 'Add a site'

กรอกชื่อโดเมนที่ต้องการจัดการ จากนั้นเลือกแพ็กเกจที่เหมาะสม หากเพิ่งเริ่มใช้งาน สามารถเลือกแพ็กเกจฟรีได้

### 2.3 ตรวจสอบ DNS Records

Cloudflare สามารถสแกน DNS Records ที่มีอยู่เดิมได้โดยอัตโนมัติ เมื่อสแกนเสร็จแล้ว ควรตรวจสอบว่าข้อมูลทั้งหมดถูกต้องหรือไม่

โดยเฉพาะ Records ต่อไปนี้:

- A Record
- AAAA Record
- CNAME Record
- MX Record

หากคุณใช้งานบริการอีเมล ควรตรวจสอบ MX Record และ TXT Record ที่เกี่ยวข้องให้ถูกต้องด้วย

### 2.4 เปลี่ยน Nameserver

นำที่อยู่ Nameserver ที่ Cloudflare กำหนดให้ ไปตั้งค่าในหน้าจัดการโดเมนของผู้ให้บริการจดทะเบียนโดเมนที่คุณใช้งานอยู่

การเปลี่ยนแปลงอาจต้องใช้เวลาสักระยะจึงจะมีผลสมบูรณ์

เมื่อเชื่อมต่อสำเร็จแล้ว คุณจะสามารถจัดการฟีเจอร์ต่าง ๆ ได้จากแดชบอร์ด Cloudflare

## 3. 10 ฟีเจอร์สำคัญของ Cloudflare ที่มือใหม่ควรรู้

## 3.1 การจัดการ DNS (DNS Management)

DNS คือระบบที่ใช้เชื่อมโยงชื่อโดเมนเข้ากับ IP Address ของเซิร์ฟเวอร์

Cloudflare ช่วยให้คุณจัดการ DNS Records ทั้งหมดได้จากที่เดียว

DNS Records ที่สำคัญ ได้แก่:

- A: เชื่อมต่อโดเมนกับ IPv4 Address
- AAAA: เชื่อมต่อโดเมนกับ IPv6 Address
- CNAME: ชี้ไปยังชื่อโดเมนอื่น
- MX: กำหนดเซิร์ฟเวอร์อีเมล
- TXT: ใช้สำหรับการยืนยันโดเมนและการตรวจสอบสิทธิ์อีเมล เป็นต้น

### ความแตกต่างระหว่าง Proxied และ DNS Only

ในหน้าจัดการ DNS ของ Cloudflare จะมีไอคอนรูปเมฆสีส้มและสีเทา

**Proxied (เมฆสีส้ม)**

ทราฟฟิกจะผ่านเครือข่าย Proxy ของ Cloudflare ทำให้สามารถใช้ CDN และฟีเจอร์ด้านความปลอดภัยบางอย่างได้

**DNS Only (เมฆสีเทา)**

Cloudflare ทำหน้าที่เฉพาะการแปลงชื่อโดเมนเป็น IP Address ส่วนทราฟฟิกจริงจะเชื่อมต่อไปยังเซิร์ฟเวอร์ต้นทางโดยตรง

สำหรับทราฟฟิก HTTP/HTTPS ของเว็บไซต์ทั่วไป คุณสามารถตั้งค่า DNS Record ที่เกี่ยวข้องเป็น Proxied เพื่อใช้บริการ Proxy และระบบป้องกันของ Cloudflare ได้

อย่างไรก็ตาม Records ของบริการที่ไม่รองรับ Proxy เช่น เซิร์ฟเวอร์อีเมล ควรตั้งค่าเป็น DNS Only

## 3.2 CDN และการเพิ่มความเร็วเว็บไซต์ (CDN)

CDN เป็นเทคโนโลยีที่ใช้เซิร์ฟเวอร์ซึ่งกระจายอยู่ในหลายพื้นที่ทั่วโลก เพื่อส่งเนื้อหาเว็บไซต์จากเซิร์ฟเวอร์ที่อยู่ใกล้ผู้เข้าชมมากที่สุด

เมื่อใช้ Cloudflare CDN คุณสามารถแคชไฟล์แบบ Static เช่น รูปภาพ CSS และ JavaScript เพื่อลดจำนวนคำขอที่ส่งไปยังเซิร์ฟเวอร์ต้นทาง

ประโยชน์หลัก ได้แก่:

- เพิ่มความเร็วในการโหลดหน้าเว็บไซต์
- ลดภาระของเซิร์ฟเวอร์ต้นทาง
- ช่วยให้ผู้เข้าชมจากต่างประเทศได้รับเนื้อหาเร็วขึ้น
- เพิ่มความเสถียรและความพร้อมใช้งานของเว็บไซต์

ผลลัพธ์จากการใช้ CDN ขึ้นอยู่กับโครงสร้างเว็บไซต์ การตั้งค่าแคช และตำแหน่งของผู้เข้าชม

## 3.3 การตั้งค่า SSL/TLS (SSL/TLS)

SSL/TLS เป็นเทคโนโลยีที่ใช้เข้ารหัสข้อมูลระหว่างผู้เข้าชมกับเว็บไซต์

Cloudflare มีโหมดการเข้ารหัส SSL/TLS ให้เลือกหลายรูปแบบ

โหมดหลักมีทั้งหมด 4 แบบ:

**Off**

ไม่มีการเข้ารหัสข้อมูล

**Flexible**

เข้ารหัสการเชื่อมต่อระหว่างผู้เข้าชมกับ Cloudflare แต่ไม่ได้เข้ารหัสการเชื่อมต่อระหว่าง Cloudflare กับเซิร์ฟเวอร์ต้นทาง

**Full**

เข้ารหัสการเชื่อมต่อทั้งหมด ตั้งแต่ผู้เข้าชมไปยัง Cloudflare และจาก Cloudflare ไปยังเซิร์ฟเวอร์ต้นทาง แต่ไม่ได้บังคับว่าต้องตรวจสอบว่าใบรับรอง SSL ของเซิร์ฟเวอร์ต้นทางออกโดยหน่วยงานออกใบรับรองที่เชื่อถือได้หรือไม่

**Full (strict)**

เข้ารหัสการเชื่อมต่อทั้งหมด พร้อมตรวจสอบความถูกต้องของใบรับรอง SSL บนเซิร์ฟเวอร์ต้นทางด้วย

หากเซิร์ฟเวอร์ต้นทางติดตั้งใบรับรอง SSL ที่ถูกต้องแล้ว โดยทั่วไปแนะนำให้ใช้โหมด 'Full (strict)'

### ข้อผิดพลาด SSL ที่พบบ่อย

- 525: เกิดขึ้นเมื่อการจับมือ SSL (SSL Handshake) ระหว่าง Cloudflare กับเซิร์ฟเวอร์ต้นทางล้มเหลว
- 526: เกิดขึ้นเมื่อ Cloudflare ไม่สามารถตรวจสอบใบรับรอง SSL ของเซิร์ฟเวอร์ต้นทางในโหมด Full (strict) ได้

หากพบข้อผิดพลาดเหล่านี้ ให้ตรวจสอบใบรับรอง SSL การตั้งค่าเซิร์ฟเวอร์ต้นทาง และการตั้งค่า Firewall

## 3.4 การจัดการแคช (Caching)

Caching คือกระบวนการจัดเก็บเนื้อหาเว็บไซต์ไว้ชั่วคราว เพื่อให้สามารถส่งเนื้อหาเดิมให้ผู้เข้าชมได้เร็วขึ้นในการเข้าชมครั้งถัดไป

การใช้ Cloudflare Cache อาจช่วยลดจำนวนคำขอที่ส่งไปยังเซิร์ฟเวอร์ต้นทาง และปรับปรุงความเร็วในการโหลดเว็บไซต์ได้

### ฟีเจอร์แคชที่สำคัญ

- แคชไฟล์ Static
- กำหนดเงื่อนไขการแคชผ่าน Cache Rules
- ลบแคชผ่าน Purge Cache
- ปรับแต่งการทำงานของระบบแคช

### วิธีใช้ Purge Cache

บางครั้งหลังจากเปลี่ยนรูปภาพหรือไฟล์ CSS บนเว็บไซต์แล้ว ผู้เข้าชมยังคงเห็นเนื้อหาเวอร์ชันเก่า

ในกรณีนี้ ให้เปิดแดชบอร์ด Cloudflare ไปที่ 'Caching' แล้วเลือก 'Purge Cache' เพื่อลบข้อมูลที่ถูกแคชไว้

อย่างไรก็ตาม ควรหลีกเลี่ยงการแคชหน้าเว็บที่มีข้อมูลแตกต่างกันตามผู้ใช้ เช่น หน้าล็อกอิน ตะกร้าสินค้า หน้าข้อมูลส่วนตัว และหน้าชำระเงิน โดยไม่ตรวจสอบการตั้งค่าให้เหมาะสมก่อน

## 3.5 การป้องกัน DDoS (DDoS Protection)

DDoS เป็นการโจมตีทางไซเบอร์ที่ส่งทราฟฟิกจำนวนมหาศาลไปยังเซิร์ฟเวอร์หรือเว็บไซต์ ทำให้ผู้ใช้งานทั่วไปไม่สามารถเข้าถึงบริการได้ตามปกติ

Cloudflare ช่วยตรวจจับทราฟฟิกที่น่าสงสัยและรับมือกับการโจมตี DDoS ผ่านเครือข่ายของตนเอง

ประโยชน์หลัก ได้แก่:

- ป้องกันทราฟฟิกที่เป็นอันตรายจำนวนมาก
- ลดภาระของเซิร์ฟเวอร์
- เพิ่มความพร้อมใช้งานของเว็บไซต์
- กรองคำขอที่น่าสงสัย

ผู้ดูแลเว็บไซต์ควรตรวจสอบการตั้งค่าความปลอดภัยและ Event Logs ของ Cloudflare เป็นประจำ เพื่อค้นหากิจกรรมหรือการเข้าถึงที่ผิดปกติ

## 3.6 Web Application Firewall (WAF)

WAF เป็นฟีเจอร์ด้านความปลอดภัยที่ช่วยตรวจจับและควบคุมคำขอที่เป็นอันตรายซึ่งมุ่งเป้าไปยังเว็บแอปพลิเคชัน

การใช้ Cloudflare WAF ช่วยเพิ่มการป้องกันการโจมตีเว็บไซต์ที่พบบ่อย เช่น SQL Injection และ Cross-Site Scripting (XSS)

ฟีเจอร์หลัก ได้แก่:

- Managed Rules: ใช้กฎความปลอดภัยที่มีการจัดเตรียมไว้แล้ว
- Custom Rules: สร้างเงื่อนไขของตนเองเพื่ออนุญาตหรือบล็อกทราฟฟิก
- ตรวจจับคำขอที่น่าสงสัย
- ควบคุมการเข้าถึงตาม IP Address ประเทศ หรือเงื่อนไขอื่น ๆ

### คำแนะนำการตั้งค่าสำหรับมือใหม่

ในช่วงแรก ควรตรวจสอบ Managed Rules ที่มีให้ใช้งาน และเปิดใช้งานกฎความปลอดภัยที่จำเป็น

อย่างไรก็ตาม การตั้งค่าบางอย่างอาจทำให้คำขอจากผู้เข้าชมทั่วไปถูกบล็อกโดยไม่ตั้งใจ

หากเว็บไซต์เกิดปัญหา ให้ตรวจสอบ Security Events เพื่อดูว่ามีการบล็อกทราฟฟิกปกติผิดพลาดหรือไม่

## 3.7 การตั้งค่า Redirect (Redirect Rules)

Redirect Rules ช่วยให้คุณเปลี่ยนเส้นทางผู้เข้าชมจาก URL หนึ่งไปยังอีก URL หนึ่งโดยอัตโนมัติ

ตัวอย่างเช่น หากคุณเปลี่ยน URL ของหน้าเว็บไซต์เดิมเป็น URL ใหม่ สามารถใช้ฟีเจอร์นี้เพื่อส่งผู้เข้าชมไปยังหน้าใหม่ได้

Redirect ที่นิยมใช้มี 2 ประเภท:

**301 Redirect**

ใช้สำหรับการเปลี่ยน URL แบบถาวร เหมาะกับกรณีที่มีการเปลี่ยนที่อยู่ของหน้าเว็บไซต์อย่างถาวร

**302 Redirect**

ใช้สำหรับการเปลี่ยน URL แบบชั่วคราว เช่น หน้าแคมเปญหรือหน้าส่งเสริมการขายที่มีระยะเวลาจำกัด

เมื่อกำหนด Redirect ควรตรวจสอบ Source URL และ Destination URL ให้ถูกต้อง

## 3.8 การวิเคราะห์ทราฟฟิก (Analytics)

Cloudflare Analytics ช่วยให้คุณตรวจสอบข้อมูลทราฟฟิกและข้อมูลด้านความปลอดภัยของเว็บไซต์ได้

ข้อมูลสำคัญที่สามารถตรวจสอบได้ ได้แก่:

- จำนวนคำขอ
- ปริมาณการใช้แบนด์วิดท์
- สถานะการใช้แคช
- เหตุการณ์ด้านความปลอดภัย
- แนวโน้มของทราฟฟิก

ข้อมูลเหล่านี้ช่วยให้คุณเข้าใจการทำงานของเว็บไซต์และตรวจสอบปัญหาที่เกี่ยวข้องกับเครือข่ายได้ง่ายขึ้น

โปรดทราบว่า Cloudflare Analytics เน้นการวิเคราะห์เครือข่ายและคำขอเป็นหลัก ส่วน Google Analytics เน้นการวิเคราะห์พฤติกรรมผู้เข้าชมและจำนวนการดูหน้าเว็บไซต์ ดังนั้นทั้งสองบริการจึงมีวัตถุประสงค์แตกต่างกัน

## 3.9 Cloudflare Workers

Cloudflare Workers เป็นสภาพแวดล้อมสำหรับรันโค้ดแบบ Serverless ที่ช่วยให้คุณสามารถเรียกใช้โค้ด เช่น JavaScript บนเครือข่ายของ Cloudflare ได้

คุณสามารถประมวลผลคำขอและสร้าง API ได้โดยไม่จำเป็นต้องจัดการเซิร์ฟเวอร์ด้วยตนเอง

การใช้งานหลัก ได้แก่:

- สร้าง API
- ประมวลผลคำขอ
- เขียน URL ใหม่
- จัดการการยืนยันตัวตนและการควบคุมการเข้าถึง
- สร้างเนื้อหาแบบไดนามิก

ฟีเจอร์และขีดจำกัดการใช้งานของ Workers ขึ้นอยู่กับแพ็กเกจและนโยบายของบริการ

## 3.10 Cloudflare Pages

Cloudflare Pages เป็นบริการโฮสติ้งที่ใช้เผยแพร่เว็บไซต์แบบ Static และโปรเจกต์ Frontend

คุณสามารถเชื่อมต่อกับ Repository เช่น GitHub เพื่อให้เว็บไซต์ถูก Deploy โดยอัตโนมัติเมื่อมีการอัปเดตโค้ด

### ขั้นตอนพื้นฐานในการเผยแพร่เว็บไซต์

1. เข้าสู่ระบบแดชบอร์ด Cloudflare
2. เปิดเมนู Workers & Pages
3. เลือกสร้างโปรเจกต์ Pages
4. เชื่อมต่อบัญชี GitHub ของคุณ
5. เลือก Repository ที่ต้องการเผยแพร่
6. กำหนด Build Command และ Output Directory
7. เริ่มกระบวนการ Deployment
8. เพิ่ม Custom Domain หากจำเป็น

บริการนี้เหมาะสำหรับผู้ที่ต้องการเผยแพร่เว็บไซต์แบบ Static เป็นครั้งแรกด้วยเช่นกัน

## 4. การตั้งค่า Cloudflare ที่แนะนำสำหรับมือใหม่

หากคุณเพิ่งเริ่มใช้ Cloudflare ไม่จำเป็นต้องเปลี่ยนการตั้งค่าทุกฟีเจอร์พร้อมกัน

ควรเริ่มจากการตรวจสอบการตั้งค่าพื้นฐานต่อไปนี้

### 4.1 ตรวจสอบ DNS Records

ตรวจสอบว่า A, AAAA, CNAME และ MX Records ได้รับการกำหนดค่าอย่างถูกต้อง

### 4.2 ตั้งค่า SSL/TLS

หากเซิร์ฟเวอร์ต้นทางมีใบรับรอง SSL ที่ถูกต้อง ให้พิจารณาใช้โหมด 'Full (strict)'

### 4.3 ใช้ CDN และระบบแคช

เปิดใช้งานการแคชสำหรับไฟล์ Static และตั้งค่า Cache Rules ตามความจำเป็น

### 4.4 ตรวจสอบฟีเจอร์ความปลอดภัย

ตรวจสอบฟีเจอร์ที่มีให้ใช้งาน เช่น DDoS Protection และ WAF

### 4.5 ตรวจสอบ Logs เป็นประจำ

ติดตาม Analytics และ Security Events เพื่อค้นหาการเข้าถึงที่ผิดปกติหรือปัญหาจากการตั้งค่า

## 5. ปัญหาที่พบบ่อยใน Cloudflare และวิธีแก้ไข

หลังจากตั้งค่า Cloudflare แล้ว บางครั้งเว็บไซต์อาจไม่สามารถเปิดได้ หรือมีข้อความแสดงข้อผิดพลาดปรากฏขึ้น

ด้านล่างนี้คือปัญหาที่มือใหม่อาจพบได้บ่อย พร้อมแนวทางแก้ไข

### 5.1 เว็บไซต์ไม่สามารถเปิดได้หลังจากเชื่อมต่อ Cloudflare

สาเหตุที่เป็นไปได้:

- ตั้งค่า DNS Records ไม่ถูกต้อง
- การเปลี่ยน Nameserver ยังไม่เสร็จสมบูรณ์
- เซิร์ฟเวอร์ต้นทางหยุดทำงาน
- ตั้งค่า SSL/TLS ไม่ถูกต้อง

วิธีแก้ไข:

1. ตรวจสอบความถูกต้องของ DNS Records
2. ตรวจสอบการตั้งค่า Nameserver ของโดเมน
3. ตรวจสอบว่าเซิร์ฟเวอร์ต้นทางทำงานตามปกติหรือไม่
4. ตรวจสอบโหมดการเข้ารหัส SSL/TLS

### 5.2 Error 522: Connection Timed Out

ข้อผิดพลาดนี้เกิดขึ้นเมื่อ Cloudflare ไม่สามารถสร้างการเชื่อมต่อกับเซิร์ฟเวอร์ต้นทางได้ หรือไม่ได้รับการตอบกลับภายในเวลาที่กำหนด

สาเหตุที่เป็นไปได้:

- เซิร์ฟเวอร์ต้นทางหยุดทำงาน
- เซิร์ฟเวอร์ตอบสนองช้าเกินไป
- Firewall บล็อกคำขอจาก Cloudflare
- เซิร์ฟเวอร์มีภาระงานสูงเกินไป

วิธีแก้ไข:

- ตรวจสอบว่าเซิร์ฟเวอร์ต้นทางทำงานตามปกติ
- ตรวจสอบการตั้งค่า Firewall ของเซิร์ฟเวอร์
- อนุญาตคำขอจาก IP Address ของ Cloudflare
- ตรวจสอบโหลดของเซิร์ฟเวอร์และสถานะเครือข่าย

### 5.3 Error 525: SSL Handshake Failed

ข้อผิดพลาดนี้เกิดขึ้นเมื่อการจับมือ SSL ระหว่าง Cloudflare กับเซิร์ฟเวอร์ต้นทางไม่สำเร็จ

วิธีแก้ไข:

- ตรวจสอบใบรับรอง SSL ของเซิร์ฟเวอร์ต้นทาง
- ตรวจสอบการตั้งค่า SSL/TLS บนเซิร์ฟเวอร์
- ตรวจสอบวิธีการเข้ารหัสและพอร์ตที่ใช้งาน
- ตรวจสอบ Logs ที่เกี่ยวข้องกับ SSL บนเซิร์ฟเวอร์

### 5.4 รูปภาพหรือไฟล์ไม่อัปเดต

บางครั้งหลังจากเปลี่ยนรูปภาพหรือไฟล์ CSS บนเว็บไซต์แล้ว เนื้อหาเวอร์ชันเก่ายังคงแสดงอยู่

สาเหตุอาจเกิดจาก Cloudflare หรือเบราว์เซอร์ยังคงเก็บข้อมูลแคชเดิมไว้

วิธีแก้ไข:

1. เปิดแดชบอร์ด Cloudflare
2. ไปที่เมนู Caching
3. เลือก Purge Cache
4. ลบข้อมูลแคชที่จำเป็น
5. รีเฟรชเบราว์เซอร์และตรวจสอบอีกครั้ง

### 5.5 แพ็กเกจฟรีของ Cloudflare เพียงพอหรือไม่?

สำหรับบล็อกส่วนตัว เว็บไซต์ขนาดเล็ก และเว็บไซต์เนื้อหาทั่วไป ฟีเจอร์พื้นฐานในแพ็กเกจฟรีอาจเพียงพอต่อการใช้งาน

แต่หากคุณต้องการฟีเจอร์ WAF ขั้นสูง เครื่องมือ Analytics เพิ่มเติม หรือการควบคุมทราฟฟิกที่ละเอียดมากขึ้น ก็สามารถพิจารณาแพ็กเกจแบบชำระเงินได้

โปรดทราบว่าฟีเจอร์และข้อจำกัดในการใช้งานอาจเปลี่ยนแปลงได้ ควรตรวจสอบรายละเอียดแพ็กเกจล่าสุดจากเว็บไซต์ทางการของ Cloudflare

## 7. สรุป

Cloudflare เป็นแพลตฟอร์มที่มีประโยชน์สำหรับการเพิ่มความเร็วเว็บไซต์ เสริมความปลอดภัย และจัดการ DNS รวมถึงงานด้านเครือข่ายอื่น ๆ

ผู้เริ่มต้นควรทำความเข้าใจฟีเจอร์พื้นฐานก่อน เช่น DNS, CDN, SSL/TLS, Caching และ DDoS Protection

หลังจากนั้นจึงค่อยเลือกใช้ WAF, Redirect Rules, Analytics, Workers และ Pages ตามความต้องการของเว็บไซต์

ไม่จำเป็นต้องเปลี่ยนการตั้งค่าทั้งหมดตั้งแต่เริ่มต้น ควรทำความเข้าใจแต่ละฟีเจอร์และทยอยนำไปใช้งานทีละขั้นตอน

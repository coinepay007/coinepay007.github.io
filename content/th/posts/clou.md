## **1. Cloudflare CDN คืออะไร?**

Cloudflare เป็นแพลตฟอร์มที่ให้บริการด้านเครือข่าย ความปลอดภัย และการเพิ่มประสิทธิภาพเว็บไซต์ หนึ่งในบริการหลักคือ CDN ซึ่งย่อมาจาก Content Delivery Network หรือเครือข่ายการกระจายเนื้อหา

CDN ทำงานโดยใช้เซิร์ฟเวอร์ที่กระจายอยู่ในหลายพื้นที่ทั่วโลก เมื่อผู้เข้าชมเปิดเว็บไซต์ ระบบจะพยายามส่งเนื้อหาที่จัดเก็บไว้จากเซิร์ฟเวอร์ที่อยู่ใกล้ผู้เข้าชม แทนที่จะดึงข้อมูลทั้งหมดจากเซิร์ฟเวอร์ต้นทางทุกครั้ง

ประโยชน์หลักของ Cloudflare CDN ได้แก่:

- **เพิ่มความเร็วเว็บไซต์:** ช่วยส่งรูปภาพ ไฟล์ CSS และ JavaScript จากเซิร์ฟเวอร์ที่อยู่ใกล้ผู้เข้าชม
- **ลดภาระเซิร์ฟเวอร์ต้นทาง:** ใช้ระบบ Cache เพื่อลดจำนวนคำขอที่ส่งไปยังเซิร์ฟเวอร์
- **เพิ่มความปลอดภัย:** มีเครื่องมือช่วยป้องกันการโจมตี DDoS และจัดการทราฟฟิกที่เป็นอันตราย
- **จัดการ DNS:** สามารถจัดการ DNS Records ของโดเมนผ่านแดชบอร์ดเดียว
- **รองรับ HTTPS:** มีการตั้งค่า SSL/TLS เพื่อช่วยเข้ารหัสการเชื่อมต่อ
- **จัดการ Cache:** สามารถกำหนดกฎการจัดเก็บเนื้อหาด้วย Cache Rules

## **2. สิ่งที่ต้องเตรียมก่อนตั้งค่า Cloudflare**

ก่อนเริ่มต้นใช้งาน ควรเตรียมข้อมูลต่อไปนี้ให้พร้อม:

1. ชื่อโดเมนของเว็บไซต์ เช่น [example.com](http://example.com)
2. สิทธิ์ในการเข้าสู่ระบบเว็บไซต์ของผู้ให้บริการจดทะเบียนโดเมน
3. ข้อมูล DNS Records ปัจจุบันของโดเมน
4. สิทธิ์ในการเข้าถึงระบบจัดการโฮสติ้งหรือเซิร์ฟเวอร์
5. ข้อมูลเกี่ยวกับใบรับรอง SSL ที่เว็บไซต์ใช้งานอยู่

แนะนำให้สำรองข้อมูล DNS Records เดิมก่อนเปลี่ยนแปลงการตั้งค่า โดยเฉพาะโดเมนที่ใช้งานอีเมลหรือเชื่อมต่อกับบริการภายนอกอื่น ๆ

## **3. สมัครบัญชี Cloudflare**

ขั้นตอนแรกคือเข้าเว็บไซต์อย่างเป็นทางการของ Cloudflare:

[https://www.cloudflare.com/](https://www.cloudflare.com/)

จากนั้นทำตามขั้นตอนต่อไปนี้:

1. คลิก Sign Up เพื่อสมัครบัญชีใหม่
2. กรอกอีเมลที่ต้องการใช้
3. ตั้งรหัสผ่านที่มีความปลอดภัย
4. ยืนยันอีเมลตามขั้นตอนที่ระบบกำหนด
5. เข้าสู่ระบบเพื่อเปิดแดชบอร์ด Cloudflare

เมื่อเข้าสู่ระบบเรียบร้อยแล้ว คุณสามารถเริ่มเพิ่มโดเมนเว็บไซต์ได้ทันที

## **4. เพิ่มโดเมนเว็บไซต์เข้าสู่ Cloudflare**

หลังจากเข้าสู่แดชบอร์ดแล้ว ให้ดำเนินการดังนี้:

1. เลือก Add a Site หรือ Add a Domain ตามชื่อเมนูที่แสดง
2. กรอกชื่อโดเมน เช่น [example.com](http://example.com)
3. คลิกดำเนินการต่อ
4. รอให้ Cloudflare ตรวจสอบและนำเข้า DNS Records ที่มีอยู่

ระบบจะพยายามค้นหา DNS Records ปัจจุบันของโดเมน เช่น A, CNAME, MX และ TXT

เมื่อการตรวจสอบเสร็จสิ้น ควรตรวจสอบข้อมูลที่นำเข้าให้ละเอียดก่อนดำเนินการต่อ เพราะหากข้อมูล DNS ไม่ถูกต้อง อาจทำให้เว็บไซต์หรืออีเมลไม่สามารถใช้งานได้

## **5. เลือกแพ็กเกจ Cloudflare**

หลังจากเพิ่มโดเมนแล้ว ระบบจะแสดงแพ็กเกจที่สามารถเลือกใช้งานได้

โดยทั่วไปมีตัวเลือกหลักดังนี้:

- **Free:** เหมาะสำหรับเว็บไซต์ส่วนตัว บล็อก และเว็บไซต์ขนาดเล็กจำนวนมาก
- **Paid Plans:** มีฟีเจอร์เพิ่มเติมด้านความปลอดภัย ประสิทธิภาพ และการควบคุมระบบ ขึ้นอยู่กับแพ็กเกจ

หากเพิ่งเริ่มใช้งาน Cloudflare สามารถเลือกแพ็กเกจ Free เพื่อทดลองใช้ฟีเจอร์พื้นฐานก่อน แล้วค่อยพิจารณาอัปเกรดเมื่อเว็บไซต์มีความต้องการเพิ่มขึ้น

## **6. ตรวจสอบ DNS Records**

DNS Records เป็นส่วนสำคัญของการตั้งค่า Cloudflare หากกำหนดค่าผิดพลาด อาจทำให้เว็บไซต์ไม่สามารถเข้าถึงได้ หรือบริการอีเมลหยุดทำงาน

DNS Records ที่ควรรู้จักมีดังนี้:

**A Record**

ใช้เชื่อมต่อชื่อโดเมนกับที่อยู่ IPv4 ของเซิร์ฟเวอร์

ตัวอย่าง:

[example.com](http://example.com) → 192.0.2.1

**AAAA Record**

ใช้เชื่อมต่อชื่อโดเมนกับที่อยู่ IPv6 ของเซิร์ฟเวอร์

**CNAME**

ใช้สร้างชื่อโดเมนย่อยที่ชี้ไปยังชื่อโดเมนอื่น

ตัวอย่าง:

[www.example.com](http://www.example.com) → [example.com](http://example.com)

**MX Record**

ใช้กำหนดเซิร์ฟเวอร์อีเมลที่รับข้อความสำหรับโดเมนนั้น

**TXT Record**

ใช้สำหรับยืนยันความเป็นเจ้าของโดเมน และกำหนดค่าบริการอีเมล เช่น SPF และ DKIM

ก่อนแก้ไข DNS Records ควรตรวจสอบค่าที่ถูกต้องจากผู้ให้บริการโฮสติ้งหรือผู้ให้บริการอีเมลของคุณ

## **7. ทำความเข้าใจ Cloudflare Proxy**

ถัดจาก DNS Records บางรายการ คุณจะเห็นตัวเลือกสำหรับกำหนดสถานะ Proxy ซึ่งมีโหมดหลักสองแบบ

**Proxied (ไอคอนรูปเมฆสีส้ม)**

เมื่อเปิดใช้งาน คำขอ HTTP(S) ที่รองรับจะผ่านเครือข่าย Cloudflare ทำให้สามารถใช้บริการ CDN และฟีเจอร์ด้านความปลอดภัยบางอย่างได้

**DNS Only (ไอคอนรูปเมฆสีเทา)**

Cloudflare จะทำหน้าที่แปลงชื่อโดเมนเป็น IP Address เท่านั้น การเชื่อมต่อของผู้เข้าชมจะไปยังเซิร์ฟเวอร์ต้นทางโดยตรง

ควรทราบว่า DNS Records สำหรับอีเมล เช่น MX ไม่ได้ทำงานในลักษณะเดียวกับ DNS Records ของเว็บไซต์ จึงไม่ควรเปิด Proxy ให้กับรายการเหล่านี้

หากไม่แน่ใจว่าควรเลือกโหมดใด ให้ตรวจสอบเอกสารของผู้ให้บริการก่อนเปลี่ยนแปลงการตั้งค่า

## **8. เปลี่ยน Nameservers ไปยัง Cloudflare**

หลังจากตรวจสอบ DNS Records แล้ว Cloudflare จะแสดง Nameservers สองรายการสำหรับโดเมนของคุณ

ตัวอย่างเช่น:

- [alice.ns.cloudflare.com](http://alice.ns.cloudflare.com)
- [bob.ns.cloudflare.com](http://bob.ns.cloudflare.com)

ชื่อข้างต้นเป็นเพียงตัวอย่างเท่านั้น คุณต้องใช้ Nameservers ที่แสดงอยู่ในบัญชี Cloudflare ของคุณจริง ๆ

ให้เข้าเว็บไซต์ที่คุณใช้จดทะเบียนโดเมน จากนั้นดำเนินการดังนี้:

1. เข้าสู่ระบบบัญชีผู้ให้บริการโดเมน
2. เปิดหน้าการตั้งค่า Nameservers
3. ลบ Nameservers เดิม หากระบบกำหนดให้เปลี่ยนทั้งหมด
4. กรอก Nameservers ทั้งสองรายการที่ Cloudflare ให้มา
5. บันทึกการเปลี่ยนแปลง

การอัปเดต DNS อาจใช้เวลาตั้งแต่ไม่กี่นาทีไปจนถึง 24 ชั่วโมงหรือมากกว่านั้นในบางกรณี

หลังจากนั้น ให้กลับไปที่แดชบอร์ด Cloudflare เพื่อตรวจสอบสถานะของโดเมน เมื่อระบบเปิดใช้งานเรียบร้อยแล้ว คุณจะสามารถจัดการ DNS และบริการอื่น ๆ ผ่าน Cloudflare ได้

## **9. ตั้งค่า SSL/TLS และเปิดใช้งาน HTTPS**

หลังจากเชื่อมต่อโดเมนแล้ว ให้ไปที่เมนู SSL/TLS ในแดชบอร์ด Cloudflare

คุณจะพบโหมดการเข้ารหัสหลายรูปแบบ ซึ่งกำหนดวิธีการเชื่อมต่อระหว่างผู้เข้าชม Cloudflare และเซิร์ฟเวอร์ต้นทาง

**Flexible**

การเชื่อมต่อระหว่างผู้เข้าชมกับ Cloudflare จะถูกเข้ารหัส แต่การเชื่อมต่อระหว่าง Cloudflare กับเซิร์ฟเวอร์ต้นทางจะไม่มีการเข้ารหัส

โหมดนี้อาจทำให้เกิดปัญหาการเปลี่ยนเส้นทาง หากเซิร์ฟเวอร์ต้นทางบังคับใช้ HTTPS อยู่แล้ว

**Full**

ใช้ HTTPS ทั้งระหว่างผู้เข้าชมกับ Cloudflare และระหว่าง Cloudflare กับเซิร์ฟเวอร์ต้นทาง แต่ไม่ได้ตรวจสอบความถูกต้องของใบรับรองบนเซิร์ฟเวอร์ต้นทางอย่างเข้มงวดเท่า Full (Strict)

**Full (Strict)**

เข้ารหัสการเชื่อมต่อทั้งสองช่วง และตรวจสอบความถูกต้องของใบรับรอง SSL/TLS บนเซิร์ฟเวอร์ต้นทางด้วย

หากเซิร์ฟเวอร์ต้นทางติดตั้งใบรับรอง SSL ที่ถูกต้องและกำหนดค่าเรียบร้อยแล้ว โดยทั่วไปแนะนำให้ใช้ Full (Strict)

ไม่แนะนำให้เลือก Flexible สำหรับเว็บไซต์ที่ติดตั้ง HTTPS บนเซิร์ฟเวอร์ต้นทางอย่างถูกต้องแล้ว เพราะอาจทำให้เกิดปัญหา Redirect Loop หรือข้อผิดพลาดในการเข้าถึงเว็บไซต์

## **10. ตั้งค่า Cache เพื่อเพิ่มความเร็วเว็บไซต์**

Cache คือระบบจัดเก็บสำเนาของเนื้อหาบางประเภทไว้ชั่วคราว ทำให้ Cloudflare สามารถส่งเนื้อหาให้ผู้เข้าชมได้โดยไม่ต้องร้องขอข้อมูลจากเซิร์ฟเวอร์ต้นทางทุกครั้ง

ไฟล์ที่มักเหมาะกับการจัดเก็บใน Cache ได้แก่:

- รูปภาพ
- ไฟล์ CSS
- ไฟล์ JavaScript
- ไฟล์ฟอนต์และไฟล์แบบคงที่อื่น ๆ

อย่างไรก็ตาม ไม่ควรตั้งค่าให้ทุกหน้าเว็บไซต์ถูก Cache โดยไม่มีการแยกประเภท

ตัวอย่างหน้าที่อาจต้องกำหนดข้อยกเว้น ได้แก่:

- หน้าล็อกอิน
- หน้าบัญชีผู้ใช้
- หน้าตะกร้าสินค้า
- หน้าชำระเงิน
- หน้าที่แสดงข้อมูลเฉพาะของผู้ใช้แต่ละคน

หากจัดเก็บหน้าเหล่านี้ไม่เหมาะสม ผู้เข้าชมอาจเห็นข้อมูลเก่าหรือเนื้อหาที่ไม่ถูกต้อง

## **11. ใช้งาน Cache Rules**

Cache Rules ช่วยให้คุณกำหนดวิธีจัดเก็บเนื้อหาของ Cloudflare ตามประเภทคำขอหรือเส้นทาง URL ที่ต้องการ

ตัวอย่างการสร้างกฎ ได้แก่:

**ตั้งค่า Cache สำหรับไฟล์แบบคงที่**

กำหนดกฎสำหรับรูปภาพ ไฟล์ CSS และ JavaScript เพื่อช่วยเพิ่มความเร็วในการโหลดเว็บไซต์

**ยกเว้นหน้าจัดการเว็บไซต์**

กำหนดให้เส้นทางอย่าง /admin หรือ /login ไม่ถูกจัดเก็บใน Cache ตามโครงสร้างเว็บไซต์ของคุณ

**กำหนดกฎสำหรับโฟลเดอร์หรือ Subdomain**

สามารถสร้างกฎที่แตกต่างกันสำหรับเส้นทาง URL หรือโดเมนย่อยแต่ละรายการได้

**กำหนดระยะเวลาการจัดเก็บ Cache**

ตั้งระยะเวลาการจัดเก็บข้อมูลให้เหมาะสมกับประเภทไฟล์และความถี่ในการอัปเดตเนื้อหา

หากเว็บไซต์ของคุณใช้ WordPress ควรระมัดระวังไม่ให้หน้าล็อกอิน หน้าจัดการเว็บไซต์ และหน้าไดนามิกถูก Cache ในลักษณะที่ส่งผลต่อการทำงานของเว็บไซต์

## **12. วิธีล้าง Cloudflare Cache**

หากคุณแก้ไขเว็บไซต์แล้ว แต่ผู้เข้าชมยังเห็นเนื้อหาเวอร์ชันเก่า สาเหตุอาจเกิดจากข้อมูลที่ถูกจัดเก็บไว้ใน Cache

สามารถแก้ไขได้ตามขั้นตอนต่อไปนี้:

1. เข้าสู่ระบบ Cloudflare
2. เลือกโดเมนที่ต้องการจัดการ
3. เปิดเมนู Caching
4. ไปที่ Purge Cache
5. เลือกล้างไฟล์ทั้งหมด หรือเลือก URL ที่ต้องการล้าง
6. ยืนยันการดำเนินการ

หากทราบว่าไฟล์ใดต้องการอัปเดต แนะนำให้ล้างเฉพาะ URL ที่เกี่ยวข้อง เพื่อลดการลบข้อมูล Cache ทั้งหมดโดยไม่จำเป็น

## **13. วิธีตรวจสอบว่า Cloudflare CDN ทำงานแล้วหรือไม่**

หลังจากตั้งค่าเสร็จแล้ว คุณสามารถตรวจสอบการทำงานของ Cloudflare ผ่านเครื่องมือสำหรับนักพัฒนาในเบราว์เซอร์ได้

ทำตามขั้นตอนดังนี้:

1. เปิดเว็บไซต์ของคุณในเบราว์เซอร์
2. กด F12 เพื่อเปิด Developer Tools
3. เลือกแท็บ Network
4. รีเฟรชหน้าเว็บไซต์
5. เลือกคำขอไฟล์ใดไฟล์หนึ่ง เช่น รูปภาพหรือไฟล์ CSS
6. เปิดส่วน Response Headers
7. ค้นหาค่า cf-cache-status

ค่าที่อาจพบมีดังนี้:

- **HIT:** เนื้อหาถูกส่งมาจาก Cache
- **MISS:** ไม่มีเนื้อหานั้นใน Cache จึงมีการร้องขอจากเซิร์ฟเวอร์ต้นทาง
- **BYPASS:** มีการข้าม Cache เนื่องจากการตั้งค่าหรือกฎที่กำหนดไว้
- **DYNAMIC:** เนื้อหาถูกจัดการเป็นข้อมูลไดนามิก และไม่ได้ถูก Cache ตามปกติ
- **EXPIRED:** ข้อมูลใน Cache หมดอายุแล้ว ระบบอาจต้องดึงข้อมูลเวอร์ชันใหม่

ไม่จำเป็นที่ทุกคำขอจะต้องแสดงค่า HIT เพราะไฟล์และหน้าเว็บบางประเภทจำเป็นต้องดึงข้อมูลจากเซิร์ฟเวอร์ต้นทางตามการตั้งค่าของเว็บไซต์

## **14. ปัญหาที่พบบ่อยในการใช้งาน Cloudflare**

ระหว่างการตั้งค่า Cloudflare คุณอาจพบข้อผิดพลาดบางประเภท ต่อไปนี้คือปัญหาที่พบบ่อยและแนวทางแก้ไข

**ข้อผิดพลาด 521: Web Server Is Down**

โดยทั่วไปหมายถึง Cloudflare ไม่สามารถเชื่อมต่อกับเซิร์ฟเวอร์ต้นทางได้ หรือเซิร์ฟเวอร์ปฏิเสธการเชื่อมต่อ

แนวทางแก้ไข:

- ตรวจสอบว่าเซิร์ฟเวอร์ยังทำงานอยู่หรือไม่
- ตรวจสอบการตั้งค่า Firewall
- ตรวจสอบว่ามีการอนุญาต IP Address ของ Cloudflare ตามความจำเป็นหรือไม่
- ตรวจสอบการตั้งค่าของเซิร์ฟเวอร์

**ข้อผิดพลาด 522: Connection Timed Out**

หมายถึงการเชื่อมต่อระหว่าง Cloudflare กับเซิร์ฟเวอร์ต้นทางใช้เวลานานเกินกำหนด

สิ่งที่ควรตรวจสอบ ได้แก่:

- ความเสถียรของเซิร์ฟเวอร์
- ความเร็วในการตอบสนองของเครือข่าย
- การตั้งค่า Firewall
- ทรัพยากรของเซิร์ฟเวอร์และความสามารถในการรองรับคำขอ

**ปัญหาใบรับรอง SSL**

หากพบข้อความเตือนเกี่ยวกับ SSL ให้ตรวจสอบโหมด SSL/TLS ใน Cloudflare และความถูกต้องของใบรับรองที่ติดตั้งบนเซิร์ฟเวอร์ต้นทาง

**เว็บไซต์แสดงเนื้อหาเก่า**

ปัญหาอาจเกิดจากข้อมูลที่จัดเก็บไว้ใน Cache ให้ลองล้าง Cache หรือตรวจสอบ Cache Rules และระยะเวลาการจัดเก็บข้อมูล

## **15. Cloudflare Free เพียงพอหรือไม่?**

สำหรับเว็บไซต์ส่วนตัว บล็อก และเว็บไซต์ขนาดเล็กจำนวนมาก แพ็กเกจ Free ถือเป็นจุดเริ่มต้นที่เหมาะสม

คุณสามารถใช้งานฟีเจอร์พื้นฐานได้ เช่น:

- การจัดการ DNS
- บริการ CDN พื้นฐาน
- ใบรับรอง SSL/TLS และการตั้งค่า HTTPS
- เครื่องมือป้องกันบางประเภท
- การตั้งค่า Cache

ส่วนแพ็กเกจแบบชำระเงินอาจมีฟีเจอร์เพิ่มเติม ขีดจำกัดการใช้งานที่สูงขึ้น และตัวเลือกขั้นสูงตามรายละเอียดของแต่ละแพ็กเกจ

ก่อนอัปเกรด ควรพิจารณาความต้องการจริงของเว็บไซต์ เช่น ปริมาณผู้เข้าชม ระดับการป้องกันที่ต้องการ และฟีเจอร์ด้านประสิทธิภาพที่จำเป็น

## **16. รายการตรวจสอบหลังตั้งค่า Cloudflare**

หลังจากตั้งค่าทั้งหมดเสร็จแล้ว ควรตรวจสอบรายการต่อไปนี้:

- เพิ่มโดเมนเข้าสู่บัญชี Cloudflare เรียบร้อยแล้ว
- ตรวจสอบ DNS Records ทั้งหมดแล้ว
- เปลี่ยน Nameservers ที่ผู้ให้บริการจดทะเบียนโดเมนแล้ว
- สถานะโดเมนใน Cloudflare แสดงว่าเปิดใช้งานแล้ว
- เลือกโหมด SSL/TLS ที่เหมาะสมแล้ว
- เว็บไซต์สามารถใช้งานผ่าน HTTPS ได้
- ตั้งค่า Proxy สำหรับ DNS Records ที่เหมาะสมแล้ว
- กำหนด Cache Rules ตามความจำเป็นแล้ว
- ยกเว้นหน้าไดนามิกและหน้าที่มีข้อมูลสำคัญจาก Cache ตามความจำเป็นแล้ว
- ทดสอบเว็บไซต์ อีเมล และบริการอื่น ๆ ที่เชื่อมต่อกับโดเมนแล้ว

## **17. สรุป**

Cloudflare CDN เป็นเครื่องมือที่มีประโยชน์สำหรับเพิ่มความเร็วเว็บไซต์ ลดภาระของเซิร์ฟเวอร์ต้นทาง และเสริมความปลอดภัยให้กับเว็บไซต์

ขั้นตอนการตั้งค่าเริ่มจากการสมัครบัญชีและเพิ่มโดเมน จากนั้นตรวจสอบ DNS Records เปลี่ยน Nameservers และตั้งค่า SSL/TLS รวมถึง Cache Rules ให้เหมาะสมกับลักษณะการใช้งาน

หากคุณเพิ่งเริ่มใช้งาน Cloudflare แนะนำให้เริ่มจากการตั้งค่าพื้นฐานและทดสอบเว็บไซต์ทุกครั้งหลังเปลี่ยนแปลงการตั้งค่า วิธีนี้จะช่วยให้ตรวจพบปัญหาได้เร็วขึ้น และลดความเสี่ยงที่จะกระทบต่อ DNS อีเมล หรือหน้าเว็บที่มีการแสดงผลแบบไดนามิก

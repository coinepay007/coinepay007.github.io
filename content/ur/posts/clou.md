# **Cloudflare CDN کیسے سیٹ اپ کریں؟ 2027 کی مکمل گائیڈ**

## **1. Cloudflare CDN کیا ہے؟**

Cloudflare ایک ایسا پلیٹ فارم ہے جو CDN، DNS، سیکیورٹی اور ویب سائٹ کی کارکردگی بہتر بنانے کے لیے مختلف سروسز فراہم کرتا ہے۔

CDN کا مکمل نام Content Delivery Network ہے۔ یہ ویب سائٹ کے مواد کو دنیا کے مختلف علاقوں میں موجود سرورز پر تقسیم اور محفوظ کرتا ہے، تاکہ وزیٹرز اپنے قریب ترین سرور سے مواد حاصل کر سکیں اور ویب سائٹ تیزی سے لوڈ ہو۔

Cloudflare کے اہم فوائد درج ذیل ہیں:

- ویب صفحات تیزی سے لوڈ ہوتے ہیں۔
- اصل سرور پر آنے والی درخواستوں کا دباؤ کم ہوتا ہے۔
- DDoS حملوں کے خلاف تحفظ ملتا ہے۔
- DNS کو آسانی سے منظم کیا جا سکتا ہے۔
- SSL سرٹیفکیٹ اور HTTPS کنکشن استعمال کیے جا سکتے ہیں۔
- Cache Rules کے ذریعے مواد کی فراہمی کو بہتر بنایا جا سکتا ہے۔

## **2. سیٹ اپ سے پہلے کیا تیار رکھیں؟**

اپنی ویب سائٹ کو Cloudflare سے منسلک کرنے سے پہلے درج ذیل چیزیں تیار رکھیں:

1. آپ کا اپنا ڈومین نام۔
2. ڈومین مینجمنٹ پینل تک رسائی۔
3. موجودہ DNS ریکارڈز کی معلومات۔
4. ہوسٹنگ یا سرور مینجمنٹ پینل تک رسائی۔

ای میل سروسز اور ڈومین سے منسلک دیگر سہولیات میں رکاوٹ سے بچنے کے لیے پہلے سے موجود DNS ریکارڈز کا بیک اپ رکھنا بہتر ہے۔

## **3. Cloudflare اکاؤنٹ بنائیں**

Cloudflare کی آفیشل ویب سائٹ پر جائیں اور ایک اکاؤنٹ بنائیں۔

رجسٹریشن مکمل ہونے کے بعد یہ مراحل اختیار کریں:

1. Cloudflare Dashboard کھولیں۔
2. Add a Site کا آپشن منتخب کریں۔
3. اپنا ڈومین نام درج کریں۔
4. سیٹ اپ کا عمل آگے بڑھائیں۔

Cloudflare خودکار طور پر آپ کے موجودہ DNS ریکارڈز کو اسکین کرکے امپورٹ کرنے کی کوشش کرے گا۔

## **4. Cloudflare میں اپنا ڈومین شامل کریں**

ڈومین نام درج کرنے کے بعد Cloudflare آپ سے ایک پلان منتخب کرنے کے لیے کہے گا۔

ذاتی ویب سائٹس اور چھوٹے پروجیکٹس کے لیے ابتدا میں Free پلان عموماً کافی ہوتا ہے۔

پلان منتخب کرنے کے بعد امپورٹ کیے گئے DNS ریکارڈز کو چیک کریں۔

## **5. DNS ریکارڈز کی جانچ کریں**

DNS ریکارڈز کی جانچ Cloudflare سیٹ اپ کے اہم ترین مراحل میں سے ایک ہے۔

Cloudflare موجودہ DNS ریکارڈز خودکار طور پر امپورٹ کر سکتا ہے، لیکن آپ کو تصدیق کرنی چاہیے کہ تمام معلومات درست طریقے سے شامل ہوئی ہیں۔

DNS ریکارڈز کی اہم اقسام یہ ہیں:

**A Record**

ڈومین نام کو IPv4 سرور ایڈریس سے منسلک کرتا ہے۔

**AAAA Record**

ڈومین نام کو IPv6 ایڈریس سے منسلک کرتا ہے۔

**CNAME Record**

کسی سب ڈومین کو دوسرے ڈومین نام کی طرف بھیجتا ہے۔

**MX Record**

ڈومین پر موصول ہونے والی ای میلز کے لیے میل سرور متعین کرتا ہے۔

**TXT Record**

ڈومین کی تصدیق، SPF، DKIM اور دیگر کنفیگریشنز کے لیے استعمال ہوتا ہے۔

اگر آپ اپنے ڈومین کے ساتھ ای میل سروس بھی استعمال کرتے ہیں تو MX اور TXT ریکارڈز کو خاص طور پر چیک کریں۔

## **6. Cloudflare Proxy فعال کریں**

DNS ریکارڈز کی فہرست میں کچھ ریکارڈز کے ساتھ بادل کی شکل کا ایک آئیکن نظر آئے گا۔

اس کے دو بنیادی موڈ ہوتے ہیں:

**Proxied – نارنجی بادل**

HTTP اور HTTPS ٹریفک Cloudflare نیٹ ورک کے ذریعے گزرتی ہے۔ اس موڈ میں CDN اور Cloudflare کی سیکیورٹی خصوصیات استعمال کی جا سکتی ہیں۔

**DNS Only – سرمئی بادل**

Cloudflare صرف DNS Resolution فراہم کرتا ہے اور ٹریفک براہِ راست اصل سرور سے منسلک ہوتی ہے۔

اگر آپ ویب سائٹ کے A اور CNAME جیسے ریکارڈز کے لیے CDN اور سیکیورٹی سہولیات استعمال کرنا چاہتے ہیں تو Proxied آپشن فعال کر سکتے ہیں۔

MX جیسے ریکارڈز، جو Proxy کو سپورٹ نہیں کرتے، انہیں DNS Only موڈ پر ہی رکھیں۔

## **7. ڈومین کے Nameserver تبدیل کریں**

DNS ریکارڈز کی جانچ مکمل ہونے کے بعد Cloudflare آپ کو دو Nameserver ایڈریس فراہم کرے گا۔

مثال کے طور پر، ان کا فارمیٹ کچھ اس طرح ہو سکتا ہے:

- [alice.ns.cloudflare.com](http://alice.ns.cloudflare.com)
- [bob.ns.cloudflare.com](http://bob.ns.cloudflare.com)

حقیقی Nameserver ایڈریس ہر ڈومین کے لیے مختلف ہوتے ہیں۔

اپنے ڈومین رجسٹرار کے اکاؤنٹ میں لاگ اِن کریں اور پرانے Nameserver کی جگہ Cloudflare کی جانب سے فراہم کردہ Nameserver درج کریں۔

تبدیلی محفوظ کرنے کے بعد DNS Propagation مکمل ہونے کا انتظار کریں۔

اس عمل میں چند منٹ سے لے کر 24 گھنٹے یا اس سے زیادہ وقت لگ سکتا ہے۔ اس کا انحصار ڈومین رجسٹرار اور DNS Propagation پر ہوتا ہے۔

## **8. SSL/TLS کنفیگر کریں**

ڈومین فعال ہونے کے بعد Cloudflare Dashboard میں SSL/TLS سیکشن کھولیں۔

یہاں آپ مختلف Encryption Modes میں سے ایک منتخب کر سکتے ہیں۔

**Flexible**

وزیٹر اور Cloudflare کے درمیان کنکشن انکرپٹ ہوتا ہے، لیکن Cloudflare اور اصل سرور کے درمیان کنکشن انکرپٹ نہیں ہوتا۔

**Full**

Cloudflare اور اصل سرور کے درمیان HTTPS استعمال ہوتا ہے، لیکن اصل سرور کے SSL سرٹیفکیٹ کی درستگی کی سختی سے جانچ نہیں کی جاتی۔

**Full (Strict)**

کنکشن انکرپٹ ہوتا ہے اور اصل سرور کے SSL سرٹیفکیٹ کی درستگی بھی چیک کی جاتی ہے۔

اگر آپ کے سرور پر درست SSL سرٹیفکیٹ انسٹال ہے تو Full (Strict) موڈ استعمال کرنا بہتر ہے۔

اگر آپ کی ویب سائٹ پہلے ہی HTTPS کے لیے درست طریقے سے کنفیگر ہے تو Flexible موڈ استعمال کرنے سے گریز کریں، کیونکہ اس سے Redirect کے مسائل پیدا ہو سکتے ہیں۔

## **9. Cache سیٹنگز کنفیگر کریں**

Cache ایک ایسی سہولت ہے جس کے ذریعے Cloudflare تصاویر، CSS فائلز اور JavaScript فائلز جیسے وسائل کو عارضی طور پر محفوظ کرتا ہے۔

اس سے وزیٹرز یہ وسائل Cloudflare سرور سے حاصل کر سکتے ہیں اور ہر درخواست کے لیے اصل سرور تک جانے کی ضرورت نہیں رہتی۔

Cache سیٹ اپ کرنے کے لیے:

1. Caching سیکشن کھولیں۔
2. دستیاب Cache سیٹنگز کا جائزہ لیں۔
3. اپنی ویب سائٹ کے لیے مناسب Cache Level منتخب کریں۔
4. وسائل کے Cache میں محفوظ رہنے کا دورانیہ مقرر کریں۔

بغیر جانچ کے تمام صفحات کو Cache کرنا مناسب نہیں ہے۔ Login Page، Shopping Cart اور صارف کی معلومات کے مطابق تبدیل ہونے والے صفحات کے لیے خصوصی قواعد کی ضرورت ہو سکتی ہے۔

## **10. Cache Rules کنفیگر کریں**

Cloudflare آپ کو Cache کے رویے کو کنٹرول کرنے کے لیے اپنی مرضی کے قواعد بنانے کی سہولت دیتا ہے۔

مثال کے طور پر، آپ درج ذیل قواعد بنا سکتے ہیں:

- تصاویر اور Static فائلز کو Cache کرنا۔
- Admin Panel کے صفحات کو Cache سے خارج رکھنا۔
- Login صفحات کو Cache سے خارج رکھنا۔
- مخصوص Subdomain کے لیے الگ قواعد بنانا۔
- مختلف قسم کے مواد کے لیے Cache کا الگ دورانیہ مقرر کرنا۔

WordPress ویب سائٹس کے لیے خاص طور پر یہ یقینی بنائیں کہ Admin صفحات اور بار بار اپ ڈیٹ ہونے والا مواد غلطی سے Cache نہ ہو جائے۔

## **11. Cloudflare Cache صاف کریں**

اگر آپ نے ویب سائٹ اپ ڈیٹ کی ہے لیکن وزیٹرز کو اب بھی پرانا ورژن نظر آ رہا ہے تو ممکن ہے کہ Cloudflare پرانے مواد کو Cache سے فراہم کر رہا ہو۔

اس مسئلے کو حل کرنے کے لیے:

1. Caching سیکشن کھولیں۔
2. Purge Cache کا آپشن منتخب کریں۔
3. اپنی ضرورت کے مطابق Cache صاف کرنے کا طریقہ منتخب کریں۔
4. کارروائی کی تصدیق کریں۔

آپ مکمل Cache صاف کر سکتے ہیں یا صرف مخصوص URL کا Cache حذف کر سکتے ہیں۔

اگر آپ ویب سائٹ کو بار بار اپ ڈیٹ کرتے ہیں تو صرف متعلقہ URL کا Cache صاف کرنا زیادہ مؤثر ہو سکتا ہے۔

## **12. چیک کریں کہ Cloudflare CDN کام کر رہا ہے یا نہیں**

سیٹ اپ مکمل ہونے کے بعد یہ جانچنا ضروری ہے کہ آپ کی ویب سائٹ کا ٹریفک واقعی Cloudflare کے ذریعے گزر رہا ہے یا نہیں۔

آپ براؤزر کے Developer Tools کھول کر لوڈ ہونے والے وسائل کے HTTP Response Headers چیک کر سکتے ہیں۔

ان میں ایک اہم Header یہ ہے:

`cf-cache-status`

اس Header میں درج ذیل ویلیوز نظر آ سکتی ہیں:

- HIT: وسائل Cache سے فراہم کیا گیا ہے۔
- MISS: وسائل Cache میں موجود نہیں تھا اور اصل سرور سے حاصل کیا گیا ہے۔
- BYPASS: Cache کو نظر انداز کیا گیا ہے۔
- DYNAMIC: وسائل کو Cache کرنے کے قابل نہیں سمجھا گیا۔
- EXPIRED: Cache میں موجود کاپی کی مدت ختم ہو چکی ہے۔

یہ ضروری نہیں کہ ہر درخواست کا نتیجہ HIT ہو۔ Dynamic صفحات براہِ راست اصل سرور سے بھی فراہم کیے جا سکتے ہیں۔

## **13. Cloudflare سیٹ اپ کے عام مسائل**

**521 Error**

اصل سرور Cloudflare کی کنکشن درخواست مسترد کر رہا ہو سکتا ہے۔

چیک کریں کہ سرور درست طریقے سے کام کر رہا ہے یا نہیں اور Firewall، Cloudflare کے IP ایڈریسز سے آنے والے کنکشنز کی اجازت دیتا ہے یا نہیں۔

**522 Error**

Cloudflare کو مقررہ وقت کے اندر اصل سرور سے جواب نہیں مل رہا ہو سکتا۔

سرور کی کارکردگی، Firewall Rules اور نیٹ ورک کنکشن کی جانچ کریں۔

**SSL Error**

Cloudflare کے SSL/TLS موڈ اور اصل سرور کے سرٹیفکیٹ کی سیٹنگز میں فرق ہونے کی وجہ سے یہ مسئلہ پیدا ہو سکتا ہے۔

SSL سرٹیفکیٹ اور منتخب کردہ Encryption Mode کو چیک کریں۔

**ویب سائٹ پر پرانا مواد نظر آنا**

پرانا ورژن اب بھی Cache میں موجود ہو سکتا ہے۔

Cache صاف کریں اور ڈومین پر لاگو Cache Rules کی جانچ کریں۔

## **14. Cloudflare Free اور Paid پلانز میں فرق**

Cloudflare کے Free پلان کے علاوہ کئی Paid پلانز بھی دستیاب ہیں۔

**Free پلان**

بلاگز، ذاتی ویب سائٹس اور چھوٹے پروجیکٹس کے لیے موزوں ہے۔ اس میں بنیادی DNS، CDN اور سیکیورٹی خصوصیات شامل ہیں۔

**Paid پلانز**

ان ویب سائٹس کے لیے موزوں ہیں جنہیں اضافی خصوصیات، جدید قواعد، زیادہ سیکیورٹی آپشنز یا خصوصی سپورٹ سروسز کی ضرورت ہوتی ہے۔

اپ گریڈ کرنے سے پہلے یہ جانچ لیں کہ اضافی خصوصیات واقعی آپ کے لیے ضروری ہیں یا نہیں۔

## **15. سیٹ اپ مکمل ہونے کے بعد چیک لسٹ**

سیٹ اپ مکمل سمجھنے سے پہلے درج ذیل نکات کی جانچ کریں:

- ڈومین Cloudflare میں شامل کر دیا گیا ہے۔
- Nameserver درست طریقے سے تبدیل کر دیے گئے ہیں۔
- DNS ریکارڈز درست طریقے سے کنفیگر کیے گئے ہیں۔
- MX اور TXT ریکارڈز محفوظ ہیں۔
- ضروری Web Records کے لیے Proxy فعال ہے۔
- SSL/TLS موڈ درست طریقے سے سیٹ کیا گیا ہے۔
- ویب سائٹ HTTPS کے ذریعے کھل رہی ہے۔
- Cache Rules کی وجہ سے Dynamic Features متاثر نہیں ہو رہے۔
- Cloudflare فعال ہونے کے بعد بھی ویب سائٹ معمول کے مطابق کام کر رہی ہے۔

## **نتیجہ**

Cloudflare CDN آپ کی ویب سائٹ کی کارکردگی، سیکیورٹی اور استحکام بہتر بنانے کا ایک مؤثر طریقہ ہے۔

ڈومین شامل کرنے، DNS ریکارڈز چیک کرنے، Nameserver تبدیل کرنے، SSL/TLS کنفیگر کرنے اور Cache کو بہتر بنانے کے بعد آپ زیادہ تکنیکی معلومات کے بغیر بھی Cloudflare کی بنیادی سہولیات سے فائدہ اٹھا سکتے ہیں۔

بہت سی ویب سائٹس کے لیے ابتدا میں Free پلان کافی ہوتا ہے۔ جیسے جیسے آپ کا پروجیکٹ بڑھتا ہے، آپ اپنی ضرورت کے مطابق اضافی خصوصیات اور Paid پلانز پر غور کر سکتے ہیں۔

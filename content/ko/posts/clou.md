## **1. Cloudflare CDN이란?**

Cloudflare는 CDN, DNS, 보안 및 웹사이트 성능 최적화 서비스를 제공하는 플랫폼입니다.

CDN은 Content Delivery Network(콘텐츠 전송 네트워크)의 약자입니다. 웹사이트의 콘텐츠를 전 세계 여러 지역에 있는 서버에 분산 저장하고, 방문자와 가까운 서버에서 콘텐츠를 제공하는 방식입니다.

Cloudflare를 사용하면 다음과 같은 장점이 있습니다.

- 웹페이지 로딩 속도 향상
- 원본 서버의 요청 부하 감소
- DDoS 공격에 대한 보호
- DNS 관리 기능 제공
- SSL 인증서 및 HTTPS 연결 지원
- 캐시 규칙을 통한 콘텐츠 전송 최적화

## **2. 설정 전에 준비해야 할 사항**

웹사이트를 Cloudflare에 연결하기 전에 다음 항목을 준비하세요.

1. 본인 소유의 도메인
2. 도메인 관리 패널에 접속할 수 있는 계정
3. 현재 사용 중인 DNS 레코드 정보
4. 호스팅 또는 서버 관리 패널에 대한 접근 권한

이메일 서비스나 도메인과 연결된 다른 서비스가 중단되지 않도록 기존 DNS 레코드를 미리 저장해 두는 것이 좋습니다.

## **3. Cloudflare 계정 만들기**

Cloudflare 공식 웹사이트에 접속하여 계정을 생성합니다.

회원가입을 완료한 후 다음 단계를 진행하세요.

1. Cloudflare 대시보드를 엽니다.
2. 사이트 추가 옵션을 선택합니다.
3. 본인의 도메인 이름을 입력합니다.
4. 설정을 계속 진행합니다.

Cloudflare는 기존 DNS 레코드를 자동으로 검색하고 가져오려고 시도합니다.

## **4. Cloudflare에 도메인 추가하기**

도메인 이름을 입력하면 Cloudflare에서 요금제를 선택하라는 화면이 나타납니다.

개인 웹사이트나 소규모 프로젝트라면 처음에는 무료 Free 요금제로 시작해도 충분한 경우가 많습니다.

요금제를 선택한 다음 가져온 DNS 레코드가 정확한지 확인하세요.

## **5. DNS 레코드 확인하기**

DNS 레코드 확인은 Cloudflare 설정에서 가장 중요한 단계 중 하나입니다.

Cloudflare가 기존 DNS 레코드를 자동으로 가져올 수 있지만, 모든 정보가 올바르게 등록되었는지 직접 확인해야 합니다.

주요 DNS 레코드 유형은 다음과 같습니다.

**A Record**

도메인을 IPv4 서버 주소에 연결합니다.

**AAAA Record**

도메인을 IPv6 주소에 연결합니다.

**CNAME Record**

하위 도메인을 다른 도메인 이름으로 연결합니다.

**MX Record**

해당 도메인으로 들어오는 이메일을 수신할 메일 서버를 지정합니다.

**TXT Record**

도메인 소유권 확인, SPF, DKIM 및 기타 설정에 사용됩니다.

도메인으로 이메일 서비스를 이용하고 있다면 MX 및 TXT 레코드를 특히 주의해서 확인해야 합니다.

## **6. Cloudflare Proxy 활성화하기**

DNS 레코드 목록에서 일부 레코드 옆에 구름 모양 아이콘이 표시됩니다.

주요 설정 방식은 다음 두 가지입니다.

**Proxied – 주황색 구름**

HTTP 및 HTTPS 트래픽이 Cloudflare 네트워크를 통과합니다. 이 설정을 사용하면 CDN 기능과 Cloudflare 보안 기능을 활용할 수 있습니다.

**DNS Only – 회색 구름**

Cloudflare는 DNS 확인 기능만 제공하며, 실제 트래픽은 원본 서버에 직접 연결됩니다.

웹사이트의 A 레코드나 CNAME 레코드에서 CDN 및 보안 기능을 사용하려면 Proxied를 활성화할 수 있습니다.

MX 레코드처럼 프록시를 지원하지 않는 레코드는 DNS Only 상태로 유지하세요.

## **7. 도메인의 네임서버 변경하기**

DNS 레코드 확인이 끝나면 Cloudflare에서 두 개의 네임서버 주소를 제공합니다.

예를 들면 다음과 같은 형식입니다.

- [alice.ns.cloudflare.com](http://alice.ns.cloudflare.com)
- [bob.ns.cloudflare.com](http://bob.ns.cloudflare.com)

실제 네임서버 주소는 도메인마다 다릅니다.

도메인을 구매한 업체의 관리 페이지에 로그인한 다음 기존 네임서버를 Cloudflare에서 제공한 주소로 변경하세요.

변경 사항을 저장한 후 DNS 전파가 완료될 때까지 기다립니다.

전파에는 몇 분이 걸릴 수도 있고, 도메인 등록 업체 및 DNS 전파 상황에 따라 24시간 이상 소요될 수도 있습니다.

## **8. SSL/TLS 설정하기**

도메인이 활성화되면 Cloudflare 대시보드에서 SSL/TLS 설정 메뉴를 엽니다.

여기에서는 여러 암호화 모드 중 하나를 선택할 수 있습니다.

**Flexible**

방문자와 Cloudflare 사이의 연결은 암호화하지만, Cloudflare와 원본 서버 사이의 연결은 암호화하지 않습니다.

**Full**

Cloudflare와 원본 서버 사이에서도 HTTPS 연결을 사용하지만, 원본 서버의 인증서 유효성을 엄격하게 검증하지는 않습니다.

**Full (Strict)**

통신을 암호화하고 원본 서버의 SSL 인증서가 유효한지도 확인합니다.

서버에 유효한 SSL 인증서가 설치되어 있다면 Full (Strict) 모드를 사용하는 것이 좋습니다.

웹사이트가 HTTPS를 올바르게 지원하고 있다면 Flexible 모드는 리디렉션 문제를 일으킬 수 있으므로 사용을 피하는 것이 좋습니다.

## **9. 캐시 설정하기**

캐시는 Cloudflare가 이미지, CSS 파일, JavaScript 파일과 같은 리소스를 임시로 저장하는 기능입니다.

이를 통해 방문자는 Cloudflare 서버에서 해당 리소스를 받아올 수 있으므로 모든 요청이 원본 서버에 전달될 필요가 없습니다.

캐시를 설정하려면 다음 단계를 진행하세요.

1. Caching 메뉴를 엽니다.
2. 사용 가능한 캐시 설정을 확인합니다.
3. 웹사이트에 적합한 캐시 수준을 선택합니다.
4. 리소스를 캐시에 저장할 기간을 설정합니다.

모든 페이지를 확인하지 않고 무조건 캐시하는 것은 권장하지 않습니다. 로그인 페이지, 장바구니 페이지, 사용자별로 내용이 달라지는 페이지에는 별도의 규칙이 필요할 수 있습니다.

## **10. Cache Rules 설정하기**

Cloudflare에서는 캐시 동작을 세부적으로 제어할 수 있는 사용자 지정 규칙을 만들 수 있습니다.

예를 들어 다음과 같은 설정이 가능합니다.

- 이미지와 정적 파일을 캐시에 저장
- 관리자 페이지를 캐시 대상에서 제외
- 로그인 페이지를 캐시 대상에서 제외
- 특정 하위 도메인에 별도의 규칙 적용
- 콘텐츠 유형에 따라 캐시 기간 다르게 설정

WordPress 웹사이트를 운영한다면 관리자 페이지나 자주 변경되는 콘텐츠가 잘못 캐시되지 않도록 주의해야 합니다.

## **11. Cloudflare 캐시 삭제하기**

웹사이트를 업데이트했는데도 방문자에게 이전 버전이 표시된다면 Cloudflare에 오래된 콘텐츠가 캐시되어 있을 수 있습니다.

이 문제를 해결하려면 다음 단계를 진행하세요.

1. Caching 메뉴를 엽니다.
2. Purge Cache 옵션을 선택합니다.
3. 원하는 캐시 삭제 방식을 선택합니다.
4. 작업을 확인합니다.

전체 캐시를 삭제할 수도 있고 특정 URL만 선택하여 삭제할 수도 있습니다.

웹사이트를 자주 업데이트한다면 관련 URL만 선택적으로 삭제하는 것이 더 효율적일 수 있습니다.

## **12. Cloudflare CDN이 정상적으로 작동하는지 확인하기**

설정이 완료되면 웹사이트 트래픽이 실제로 Cloudflare를 통해 전달되는지 확인해야 합니다.

브라우저의 개발자 도구를 열고 로드된 리소스의 HTTP 응답 헤더를 확인할 수 있습니다.

특히 다음 헤더를 확인하는 것이 좋습니다.

`cf-cache-status`

이 헤더에는 다음과 같은 값이 표시될 수 있습니다.

- HIT: 리소스가 캐시에서 제공됨
- MISS: 캐시에 리소스가 없어 원본 서버에서 가져옴
- BYPASS: 캐시가 우회됨
- DYNAMIC: 캐시 대상으로 처리되지 않음
- EXPIRED: 캐시에 저장된 데이터의 유효기간이 만료됨

모든 요청에서 HIT가 표시되어야 하는 것은 아닙니다. 동적 페이지는 원본 서버에서 직접 제공될 수 있습니다.

## **13. Cloudflare 설정 시 자주 발생하는 문제**

**521 오류**

원본 서버가 Cloudflare의 연결 요청을 거부하는 경우 발생할 수 있습니다.

서버가 정상적으로 작동하는지, 방화벽이 Cloudflare IP 주소에서 들어오는 연결을 허용하는지 확인하세요.

**522 오류**

Cloudflare가 원본 서버로부터 제한 시간 내에 응답을 받지 못한 경우 발생합니다.

서버 성능, 방화벽 규칙 및 네트워크 연결 상태를 확인하세요.

**SSL 오류**

Cloudflare의 SSL/TLS 모드와 원본 서버의 인증서 설정이 일치하지 않을 때 발생할 수 있습니다.

SSL 인증서와 선택한 암호화 모드를 확인하세요.

**웹사이트에 이전 콘텐츠가 표시되는 문제**

이전 버전의 콘텐츠가 캐시에 남아 있을 수 있습니다.

캐시를 삭제하고 해당 도메인에 적용된 캐시 규칙을 확인하세요.

## **14. Cloudflare Free와 유료 요금제 비교**

Cloudflare는 무료 Free 요금제 외에도 여러 유료 요금제를 제공합니다.

**Free 요금제**

블로그, 개인 웹사이트 및 소규모 프로젝트에 적합합니다. 기본적인 DNS, CDN 및 보안 기능을 제공합니다.

**유료 요금제**

추가 기능, 고급 규칙 설정, 확장된 보안 옵션 또는 별도의 지원 서비스가 필요한 웹사이트에 적합합니다.

유료 요금제로 업그레이드하기 전에 추가 기능이 실제로 필요한지 확인하는 것이 좋습니다.

## **15. 설정 완료 후 체크리스트**

설정이 올바르게 완료되었는지 확인하려면 다음 항목을 점검하세요.

- 도메인이 Cloudflare에 추가되어 있는가?
- 네임서버가 올바르게 변경되었는가?
- DNS 레코드가 정확하게 설정되어 있는가?
- MX 및 TXT 레코드가 유지되어 있는가?
- 필요한 웹 레코드에서 Proxy가 활성화되어 있는가?
- SSL/TLS 모드가 올바르게 설정되어 있는가?
- 웹사이트가 HTTPS로 정상 접속되는가?
- 캐시 규칙이 동적 기능에 영향을 주지 않는가?
- Cloudflare 활성화 후에도 웹사이트가 정상적으로 작동하는가?

## **결론**

Cloudflare CDN은 웹사이트의 성능, 보안 및 안정성을 개선할 수 있는 효과적인 서비스입니다.

도메인 추가, DNS 레코드 확인, 네임서버 변경, SSL/TLS 설정 및 캐시 최적화 과정을 완료하면 전문적인 기술 지식이 많지 않아도 Cloudflare의 기본 기능을 활용할 수 있습니다.

대부분의 웹사이트는 처음에 무료 요금제만으로도 충분히 시작할 수 있습니다. 프로젝트 규모가 커지면 추가 기능이 필요한지 검토하고 적합한 요금제를 선택하면 됩니다.
